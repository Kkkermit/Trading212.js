Every error the library throws extends `Trading212Error` and carries:

| Field          | Holds                                                           |
| -------------- | --------------------------------------------------------------- |
| `code`         | A stable name, such as `missing_scope`, for `switch` statements |
| `hint`         | What to do about it, in plain English                           |
| `status`       | The HTTP status, if there was a response                        |
| `request`      | `{ method, path, endpoint }`, never headers or credentials      |
| `rateLimit`    | What the rate-limit headers said                                |
| `body`         | The response body, parsed and redacted                          |
| `apiCode`      | Trading 212's own code, from `code` or a problem-details `type` |
| `resumeCursor` | On a failed history iteration, where to carry on                |
| `toLog()`      | All of the above as a plain object, safe to hand to any logger  |

`instanceof` works on every class, even when ESM and CommonJS copies of the package are both loaded.
`isTrading212Error(value)` checks for any of them.

```ts
import { isTrading212Error, MissingScopeError } from "@kkermit/trading212.js";

try {
	await t212.history.dividends.list();
} catch (error) {
	if (error instanceof MissingScopeError) console.log(`Make a key with ${error.scope} ticked.`);
	else if (isTrading212Error(error)) console.log(error.code, error.hint);
	else throw error;
}
```

## Before anything is sent

### `ConfigurationError`

Code `configuration`. The options, or the environment variables behind `fromEnv()`, are wrong. `error.field` names
the option. Common causes: no `environment`; whitespace around the key; the key pasted into `apiSecret`; `prod` or
`paper` instead of `live` or `demo`, which the hint corrects.

### `ValidationError`

Code `validation`. The request was invalid. When the client caught it before sending, `error.issues` lists every
field at fault. Trading 212 refusing a request with 400 gives the same class.

### `TradingDisabledError`

Code `trading_disabled`. An order, cancellation or pie change on a client with trading off, which is the default on
live and behind a custom `baseUrl`. Nothing was sent. Pass `trading: "enabled"`, or `{ dryRun: true }` to preview.

### `InstrumentNotFoundError`

Code `instrument_not_found`. `instruments.resolve()` found nothing, or several equally good matches.
`error.suggestions` lists the closest.

## Refused by Trading 212

### `AuthenticationError`

Code `authentication`, status 401. Trading 212 refused the key and secret. Check both were copied exactly. **A key
works in one environment only**: a key made in practice mode is refused by live, and the other way round.
`error.environment` says which this client used.

### `MissingScopeError`

Code `missing_scope`, status 403. The key exists but lacks a permission; `error.scope` names it, such as
`orders:execute`. Make a key with it ticked. `npx @kkermit/trading212.js doctor` shows every missing permission at
once.

### `NotAvailableInDemoError`

Code `not_available_in_demo`, status 403. The feature only exists on live. CSV exports are the expected case, which
has not yet been confirmed against demo.

### `PermissionError`

Code `permission`, status 403. Any other refusal. If the key is restricted to IP addresses, check this machine's
public address is on its list.

### `OrderRejectedError`

Code `order_rejected`, status 400. Trading 212 refused an order; nothing was traded. `error.reason`:

| Reason                         | Fix                                                                        |
| ------------------------------ | -------------------------------------------------------------------------- |
| `InsufficientFreeForStocksBuy` | Not enough free cash; check `cash.availableToTrade`                        |
| `SellingEquityNotOwned`        | Selling more than available; shares in pies or pending orders do not count |
| `MarketClosed`                 | Check `exchanges.status(ticker)`                                           |
| `QuantityPrecisionMismatch`    | More than 4 decimal places; use `truncateQuantity()`                       |
| anything else                  | Trading 212's own code, passed through                                     |

### `NotFoundError`

Code `not_found`, status 404. For `orders.get()` this usually means the order has filled or been cancelled: look in
`history.orders`.

### `RateLimitError`

Code `rate_limited`, status 429. Out of budget; `error.retryAfterMs` and `error.resetAt` say when it resets. Reads
retry by themselves when the wait is short. Also thrown before sending when the client would have to wait longer than
`maxRateLimitWaitMs`.

### `ServerError`, `HttpError` and `UnexpectedResponseError`

Codes `server` (5xx), `http_error` (any other status) and `unexpected_response` (a response the client could not
read, including a redirect it refused to follow with your credentials).

## When the outcome is unclear

### `OrderOutcomeUnknownError`

Code `outcome_unknown`. **An order, cancellation or pie change may or may not have happened**: it timed out, the
connection dropped, the call was aborted after sending, Trading 212 answered 5xx or with a redirect, or it answered
with a success the client could not read. `error.sent` holds what was sent.

<Aside type="danger" title="Never resend blindly">
	Check `orders.list()` and `history.orders.list()` before trying again. The first attempt may have filled.
</Aside>

### `TimeoutError`

Code `timeout`, status 408 or the client's own `timeoutMs`. No answer in time. Reads are retried; this one ran out of
attempts. A trade that times out is an `OrderOutcomeUnknownError` instead.

### `NetworkError`

Code `network`. The connection failed. `error.sent` is `false` when it failed before reaching Trading 212 (DNS, a
refused connection, TLS), which makes even an order safe to try again.

## Error bodies

Trading 212's spec documents no error body, and these shapes have not yet been confirmed against the API.
`parseErrorBody()` reads problem details (`{ type, title, status, detail }`), `{ code, clarification }`,
`{ code, message }`, plain text and an empty body, so an unknown shape still gives a useful error. Bodies are redacted
before they are kept.
